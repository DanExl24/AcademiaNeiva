🧭 ORDEN CORRECTO PARA CONSTRUIR TU SISTEMA (FRONTEND)

🧭 📌 Landing Page (Multi-colegio) — Definición formal para el documento
🎯 Propósito

La landing page funciona como el punto de entrada público del sistema, permitiendo:

Presentar la plataforma a múltiples instituciones educativas
Captar nuevos colegios interesados en el sistema
Redirigir a procesos de autenticación o solicitud de acceso
Diferenciar claramente la información institucional del sistema vs. la de cada colegio
🧠 🏗️ Enfoque conceptual (clave para tu arquitectura)

Esto NO es:

❌ “Página del Colegio Neiva”
❌ “Sistema de un solo colegio con login bonito”

Esto SÍ es:

✅ Plataforma central multi-colegio (tenant-based system)
✅ Cada colegio es una “instancia lógica” dentro del sistema
🧩 🧾 Estructura funcional de la Landing Page
1. 🏠 Hero Section (impacto inicial)
Nombre del sistema (ej: Sistema de Gestión Académica)
Subtítulo: solución para matrícula + notas + boletines
CTA principal:
“Ingresar al sistema”
“Solicitar acceso para mi institución”
2. 🏫 Módulo “¿Eres un colegio?”
Formulario de registro de institución:
Nombre del colegio
Código DANE
Contacto
Correo institucional
Estado: solicitud pendiente de aprobación (por directivo/admin global)

📌 Esto es clave: aquí nace el “multi-tenant”.

3. 🔐 Acceso al sistema
Login general
Selección de institución (si no hay subdominio)
Ej: dropdown “Selecciona tu colegio”
O alternativa PRO:
colegio.sistema.com/login
4. 📊 Beneficios del sistema
Matrícula digital
Boletines automáticos
Seguimiento académico en tiempo real
Reportes estadísticos
Control de asistencia
5. 👥 Roles soportados
Directivos
Docentes

Estudiantes
6. 📈 Sección de confianza (opcional pero útil)
“Sistema escalable”
“Basado en PostgreSQL + arquitectura modular”

7. 📞 Contacto / soporte
Email
