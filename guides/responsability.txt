🧱📐 Mini Doc — Arquitectura por responsabilidades (Frontend + Backend)
🎯 Idea central

Cada capa del sistema tiene un trabajo claro:

Frontend = experiencia del usuario (UI + interacción)
Backend = reglas del negocio + seguridad + datos
Base de datos = persistencia confiable, no lógica emocional

Si una capa empieza a hacer el trabajo de otra… el sistema se vuelve spaghetti premium.

🎨 FRONTEND (Vue 3 + TypeScript)
🧠 Responsabilidad principal

👉 Mostrar datos y capturar acciones del usuario

❌ NO debe hacer:
Validaciones críticas de negocio (ej: “puede o no matricularse”)
Cálculos finales de notas o promedios oficiales
Decisiones de seguridad
Acceso directo a reglas del sistema
✅ SÍ debe hacer:
🖼️ UI / UX
Formularios (matrícula, login, notas)
Dashboards (docente, directivo, estudiante)
Tablas, filtros, gráficos
🔄 Estado local/global
Pinia: sesión, usuario, filtros
vue-router: navegación por roles
📡 Consumo de API
Llamar backend (GET/POST/PUT/DELETE)
Mostrar resultados
Manejar loading/error states
⚠️ Validación ligera (solo UX)
Campos vacíos
formatos de correo
longitud mínima de contraseña

Esto es solo para “no molestar al backend con basura”, no para decidir reglas del sistema.

⚙️ BACKEND (Express + TypeScript)
🧠 Responsabilidad principal

👉 Control total de la lógica del sistema

❌ NO debe hacer:
Render de UI
Decisiones basadas en frontend (“si vino bonito entonces acepto”)
Lógica duplicada sin control de negocio
✅ SÍ debe hacer:
🧩 Reglas de negocio (CORE)
Validar matrícula (cupos, estado, fechas)
Control de notas (escala, periodos, porcentajes)
Cierre de periodo académico
Estados del estudiante (activo, expulsado, etc.)
🔐 Seguridad
Autenticación (JWT)
Autorización por roles (RBAC)
Validación de acceso por id_colegio
🗄️ Gestión de datos
CRUD real
relaciones entre tablas
integridad de datos
📄 Generación de información
Boletines
reportes académicos
promedios finales



🧱📁 Responsabilidades por carpeta — Stack Vue + Express + TypeScript + Postgres
🎨 FRONTEND (Vue 3 + Vite + TypeScript)
📁 src/

👉 Núcleo del frontend

Orquesta toda la aplicación
Conecta vistas, componentes y servicios
📁 assets/

👉 Recursos estáticos

imágenes
logos del colegio
iconos locales
estilos globales no dinámicos

📌 No lógica. Solo recursos.

📁 components/

👉 Bloques reutilizables de UI

botones
modales
inputs personalizados
cards
tablas genéricas

📌 Regla: si se usa en más de una página, vive aquí.

📁 pages/ o views/

👉 Pantallas completas del sistema

Ejemplo:

Login
Dashboard Docente
Dashboard Directivo
Formulario de matrícula
Boletín

📌 Aquí se arma la experiencia completa del usuario.

📁 router/

👉 Control de navegación

rutas por rol
protección de rutas (guards)
redirecciones

📌 Ej: estudiante no puede entrar a panel docente.

📁 stores/ (Pinia)

👉 Estado global del sistema

usuario autenticado
colegio seleccionado
tokens
filtros globales

📌 Es la memoria viva del frontend.

📁 services/ o api/

👉 Comunicación con backend

axios/fetch wrappers
llamadas HTTP organizadas por módulo

Ejemplo:

auth.service.ts
notas.service.ts
matricula.service.ts

📌 Regla: aquí NO hay UI, solo datos.

📁 composables/

👉 Lógica reutilizable de Vue

hooks personalizados
lógica compartida entre componentes

Ej:

useAuth()
useNotas()

📌 Es el “backend mental” del frontend.

📁 utils/

👉 Funciones puras

formateo de fechas
validaciones simples
helpers matemáticos

📌 Sin estado, sin API, sin drama.

⚙️ BACKEND (Node.js + Express + TypeScript)
📁 src/

👉 Núcleo del backend

API
lógica de negocio
integración con DB
📁 routes/

👉 Definición de endpoints

Ej:

/auth
/estudiantes
/notas
/matriculas

📌 Solo enruta, NO ejecuta lógica pesada.

📁 controllers/

👉 Entrada de cada request

recibe req/res
valida entrada básica
llama servicios

📌 Es el “recepcionista”, no el cerebro.

📁 services/

👉 Lógica de negocio real

validar matrícula
calcular promedios
cerrar periodos
generar boletines

📌 Aquí vive el sistema de verdad.

📁 models/ o prisma/

👉 Acceso a base de datos

Prisma schema o modelos
queries estructuradas

📌 No lógica, solo datos.

📁 middlewares/

👉 Filtros del sistema

autenticación JWT
autorización por roles
validación de colegio (id_colegio)
manejo de errores

📌 Es el “seguridad privada” del backend.

📁 validators/

👉 Validación de datos de entrada

zod schemas
reglas de formato
validación de payloads

📌 Evita basura entrando al sistema.

📁 config/

👉 Configuración global

conexión a PostgreSQL
variables de entorno
configuración de CORS
JWT secret

📌 Todo lo que cambia por entorno.

📁 utils/

👉 Funciones reutilizables

formateo de fechas
helpers de cálculo
generación de códigos

📌 Sin lógica de negocio pesada.

📁 modules/ (opcional pero PRO)

👉 Organización por dominio

Ejemplo:

modules/
  estudiantes/
  notas/
  matricula/
  boletin/

Cada módulo puede contener:

routes
controller
service
validator

📌 Esto escala como sistema real, no como tutorial.
